# 0.5.0 变更说明（源码审阅，未运行安全专项验证）

新增接口参数仅接受短 ASCII 名称，不接受路径或可执行文件参数；底层 argv 继续逐项引用。每接口分离私有数据、事务、计划和流量，wg 保持兼容路径。共享写锁串行 UCI 提交。RPC 未增加通用执行或界面启用管理入口，现有 ACL 边界保留。

预览绑定目标接口、监听端口和全部接口地址；界面禁止弹窗期间切换目标，丢弃前一目标的晚到轮询响应。多池排除全部服务端地址及各网段边界，检查全部地址已应用及全部直连路由存在。

这些是源码层面的设计和检查说明，不能替代多接口运行、事务回滚、授权或设备验证。以下旧审查内容按其版本理解。

# 0.4.0 自动地址适配范围

地址池来自已提交的 wg IPv4/前缀；额外只读核对运行接口地址和直连路由。默认示例不代替实际配置。自动分配避开本地地址与已占用范围，/8–/30 范围使用区间跳过。

预览绑定 wg/LAN 配置，写后指纹包括配置与运行地址。旧网段记录保留，不自动重编号；仅明确操作可迁移，缺失 Peer 的事务保存 absent_before 并据此回滚。恢复跳过池外地址，旧路由没有模式标记时按自定义保留。

新模式字段和新网段不是旧版本的可读状态；不得在未完成事务期间直接降级。服务端公钥、单目标归属、显式接管及不重启网络/不写路由防火墙边界保留。本次未运行功能测试，下面审查均是分版本历史记录。

# 0.3.1 变更范围

移除首次启用及持久状态读取中“至少 3 个受保护客户端”的定制限制；支持空集合。服务端身份校验、接口/端口/网段检查、实际既有客户端保护、显式接管、操作预览、漂移检查与事务边界继续保留。本版未运行功能测试。以下为分版本历史设计与审查记录。

# 0.3.0 变更范围

用户明确取消原有三个客户端的保护要求。本版在 root 通过 manage-existing 接管后，允许对这些 Peer 的 UCI 配置节作定向写入；此前“不写 /etc/config/network”的设计只适用于下方历史版本。防火墙、接口参数、网络服务重启等权限边界仍保留。

接管不修改原始运行配置，仅在 root 私有目录备份原配置及建立引用。预览及提交均校验 Peer、公钥、UCI 节与选定配置；独立 UCI savedir 避免应用其他界面的暂存改动。后端没有提供任意节名、任意文件或任意命令 RPC。

旧 Peer 的备份/事务含 PSK 等秘密，保存在 0700 目录内的 0600 文件，状态与 doctor 均以白名单过滤。没有客户端私钥的旧 Peer 无法导出。事务异常可同时回退选定 UCI 节和运行 Peer；外部修改后拒绝盲目恢复。

接管后可删除原三个 Peer，故不再以“至少三个受保护公钥”约束已接管状态。服务器公钥仍固定，读写门、锁、预览令牌、并发修订、密钥输入方式继续有效。用户应保留能管理路由器的连接，所选 Peer 的禁用/删除会使它断开。

# WireGuard Manager 0.1.0 原型审查与 0.2.0 安全设计

审查日期：2026-10-18（Asia/Shanghai）。审查对象来自原项目 `WireGuard-Manager-source.zip`：README、LuCI 菜单 JSON、dashboard.js、dashboard.css。原 ZIP 不含旧 IPK 的 control、安装脚本或构建脚本，因此**无法据此证明旧 IPK 的安装行为**。本次新 IPK 的包内容另外完整检查。

## 审查结论

原型确实是只读监控页面：调用已有 `luci.wireguard.getWgInstances`，没有发现 UCI 写入、`wg set`、网络/防火墙重启命令、外部二维码服务或把私钥写入页面的代码。字符串在 DOM 节点中以文本使用，原型中没有发现明确的名称 HTML 注入点。

原型不能直接扩展成不受限制的管理页面。下面列出需要处理的缺陷、功能边界和上线前事项；没有把“未实现”当作已证实的可利用漏洞。

| 项目 | 原型问题或边界 | 0.2.0 处理 |
| --- | --- | --- |
| 持久配置与运行状态 | 只列运行中的 Peer；禁用、未装载客户端不会完整显示 | 只读 UCI、内核运行状态、插件管理记录取并集 |
| AllowedIPs 展示 | 上游旧 `getWgInstances` 实现可能在无 Endpoint 时不填 AllowedIPs | 直接从只读 UCI 和经过过滤的 dump 读取 |
| 权限依赖 | 菜单依赖整个 `luci-proto-wireguard` 权限组，缺少自身清晰边界 | 独立 status、manage、secrets ACL；不授权通用文件/执行/UCI API |
| IP 排序 | `/\d+$/` 会把 `.2/32` 和 `.10/32` 都按 `32` 排序 | 按完整 IPv4 数值排序 |
| 速度计时 | `Date.now()` 受客户端系统时钟跳变影响 | `performance.now()`；计数下降和轮询恢复首样本显示 0 |
| 累计含义 | 只有当前内核计数，接口重建后重置 | 显示本次接口计数和独立采样累计，并说明误差 |
| 写入管理 | 原型不存在，未具备事务/并发/恢复设计 | 只管理新客户端，单 Peer 事务、锁、预览、回滚、恢复 |
| 私钥来源 | 旧客户端私钥通常不在服务器，不能凭公钥恢复 | 旧客户端不提供二维码/下载；新客户端密钥单独受控保存 |
| 安装包来源 | 原 ZIP 没有旧包的打包元数据 | 增加确定性打包脚本及包结构检查；不含安装重启脚本 |

## 对用户环境的明确约束

- 仅使用现有 `wg`，UDP 51820，`192.168.66.1/24`。不添加第二套 WireGuard 服务或监听端口。
- 首次启用至少识别 3 个原有客户端，固定服务端公钥并保留保护集合。
- 不写 `/etc/config/network`、`/etc/config/firewall` 或 OpenClash、Tailscale、Lucky 配置。
- 不调用 netifd 的接口启停/重载，不执行 `wg setconf`、`wg syncconf`、`ip route add/del` 或防火墙命令。
- 原有客户端不提供修改、禁用、删除入口，目标公钥不能从 API 传入来覆盖。
- 插件客户端单独保存于 `/etc/wgmanager`；因此原 LuCI 接口页面不会显示它们。
- 安装后仍为只读；管理开关只能由本机 root CLI 打开，不属于 RPC 方法。

## 密钥与权限

所有 WireGuard 私钥和 PSK 经工具的标准输入/私有临时文件传递，不放入进程参数。客户端秘密只保存在 root 私有目录 `0700` 中、文件 `0600`，普通状态返回使用显式字段白名单；服务端私钥从 dump 的首行立即丢弃，不写入插件管理记录。真实工具集成检查确认状态、命令参数中没有私钥。

导出 RPC 单独放在 secrets 写权限中；状态读取权限没有导出权限。插件没有自己的登录、Web 服务或公网入口，复用现有 LuCI/rpcd 会话与 ACL。管理员 root 本身拥有系统权限，本插件不试图阻止已取得 root shell 的人修改路由器。

LuCI 显式点击“二维码 / 配置”后才取回秘密；关闭对话框会清空 textarea 值及二维码来源。二维码由本机 `qrencode` 生成，以 `<img>` 资源显示，不作为 HTML 插入，不向外部网站提交配置。浏览器真实会话与主题仍需设备验收。

## 事务与故障恢复

1. root 私有运行目录中的文件锁排斥并发采样与管理；第二个进程收到 `BUSY`，不阻塞现有 VPN。
2. 预览验证操作类型、字段白名单、IPv4、冲突、Peer 归属、运行状态、服务端身份，生成 192 位随机一次性令牌。
3. 令牌绑定 rpcd 会话、修订号、系统启动标识和单调时钟，60 秒过期。uhttpd 的 ubus 实现会注入真实会话，并拒绝客户端自行覆盖会话字段。
4. 提交再次检查身份、修订号、冲突和目标状态；生成新客户端密钥时再检查公钥重复。
5. 涉及内核运行状态时先持久保存事务记录，再只调用 `wg set wg peer <指定公钥> ...`。改名和导出设置不触碰内核。
6. 验证目标及其他 Peer 的稳定配置（允许 Endpoint/握手自然变化），原子保存管理状态后清理事务。回滚也只作用于该目标。
7. 进程中断、保存/验证失败且回滚未完成时，事务文件保留，后续管理全部锁定。`recover` 仅回退记录中的单个新客户端；管理数据被外部改动、服务端身份不符或归属不能确认时拒绝覆盖。

该设计不能让“删除选中客户端”同时“保持选中客户端不断线”。禁用、删除、改地址以及相关回滚可能影响被选中的插件客户端；保护目标是保留原有客户端及其他服务。首次验收继续通过原受保护客户端远程连接。

## 开机恢复、采样与卸载

`ifup` 钩子只在系统已自行启用 `wg` 后运行，只恢复插件拥有的 Peer。它不会调用 `ifup` 本身，也不会为了恢复去重启接口。发现冲突或未完成事务时停止恢复并保留证据。

可选 procd 服务只读取计数，默认不启动、不启用。内存采样每 10 秒、累计每 15 分钟保存，不能承诺计费级准确性。突然断电和采样期间的计数重置会造成遗漏。

安装包没有 `preinst`、`postinst` 或 `postrm`；卸载/升级的 `prerm` 只停止本插件的可选采样服务，并在真正卸载时取消该服务自启。它不删除任何 VPN Peer。插件卸载后其客户端失去插件开机恢复能力，原有 3 个客户端不受此存储机制影响。

## 未完成的设备验收与版本边界

- 未连接、安装或修改用户真实路由器；真实内核 netlink 行为、LuCI/rpcd 权限、包管理兼容性和真实重启恢复均未在该机验证。
- 后端测试使用 24.10 分支指定提交的 ucode、真实宿主构建 UCI/fs、真实 WireGuard 密钥工具与二维码工具；内核 Peer 操作用模拟器接收。
- 当前执行环境阻止浏览器所需的本地套接字，真实 Chrome 启动失败；DOM 交互测试通过不等于手机布局或真实 LuCI 主题已经验证。
- 旧客户端接管、旧私钥导入、修改服务端网段/端口/密钥、月度账单统计不属于这个阶段的实现。旧客户端继续只读保护。
- 私钥在 root 权限内按原生配置习惯明文存储，没有增加磁盘加密；导出的配置文件和二维码同样是秘密。
- 不与外部管理员对同一插件 Peer 的同时修改争夺控制权；发现状态冲突时要求停止操作检查，不自动覆盖或重建整套配置。
