# 0.5.0 常见问题

## 同一 WireGuard 接口能使用两个 IPv4 网段吗？

本版实现按全部 IPv4 子网生成多个池。两段均须保存并应用，有对应直连路由。新增/编辑提示同时展示；手填可选任一池，留空按配置顺序分配。旧客户端属于任一池就不再提示地址需调整。单个客户端仍只有一个 IPv4 /32。多网段功能尚待本版设备验收。

## 自动 AllowedIPs 是否包含第二个网段？

包含所选接口全部 IPv4 子网和可解析的 LAN 子网，去重最多 64 项。自定义模式不会改用户填写的内容；旧的手工路由升级后仍是自定义。已导入手机的配置不会被远程更新。

## 接口不叫 wg 或有多个 WireGuard 接口怎么办？

单接口自动识别，多个时在页面顶部选择。每次 RPC 和操作预览明确目标；列表、管理模式、地址池、流量和导出设置分别保存。导出监听端口也读取实际接口。CLI 使用 `wgmanager interfaces` 和 `wgmanager --interface vpn0 doctor`。多个接口时写命令不能省略目标。

## 升级后选择接口没有效果？

本版 RPC 参数定义变化，升级后执行 `/etc/init.d/rpcd restart`，重新登录并强制刷新浏览器。它只重启 LuCI 的 RPC 服务，没有重启网络和 WireGuard。不要靠更改网页 disabled 属性绕过管理检查。

## 为什么仍显示地址未应用？

UI 已保存的配置可能与运行状态不同；本版核对全部地址，而不只看第一项。先在 iStoreOS 网络页面保存并应用，核对真实运行地址。缺少任一地址或对应直连路由时先阻止写 Peer，并显示原因。

## 原 wg 的管理状态会丢吗？

不会主动搬迁或删除原目录，wg 沿用原状态、流量、密钥与备份。其他名字使用独立目录，新目标先只读。将 wg 重命名为新名称不会自动搬迁旧私钥和管理记录；旧目录保留，需明确核对后再决定迁移。

## 其他限制

每接口最多 16 个 /8–/30 IPv4 网段和 128 个管理客户端。IPv6、创建服务端、网络/防火墙/NAT配置、公网映射端口独立设置不在本版范围。只有运行设备但无对应 UCI 配置的接口可发现，不能管理。本版仅静态检查，尚无功能或设备通过记录。

以下为历史问答，版本限制按对应标题理解；0.5.0 已替代其中固定接口、固定端口和只取首个 IPv4 网段的说明。

# 0.4.0 常见问题

## wg 的 IP 变了，地址池和弹窗说明会跟着变吗？

会。按当前 wg 主 IPv4/前缀推导地址池，概览与弹窗读取同一份后端字段。配置必须已应用到运行接口并存在直连路由，未应用时阻止写入。详见 [地址自动适配](ADDRESS-CONFIGURATION.md)。

## 旧客户端会自动换号吗？

不会自动改设备配置。已管理的旧地址记录会保留并标记地址需调整，可以明确编辑到新池，随后同步手机/电脑配置。恢复流程跳过旧网段，避免重新添加已不属于当前池的地址。

## 导出路由会自动变化吗？

新安装默认自动跟随 wg 和 LAN 子网。旧版已经保存的路由按自定义保留，不猜测用户意图；需要时在导出设置切换到自动。自定义的 0.0.0.0/0 等设置不会被覆盖。已导入设备的配置仍要同步更新。

## 为什么没有 wg 接口时还显示默认地址？

192.168.66.1/24 仅是未配置时的展示默认值，不会被写入网络配置，也不能代替实际接口来开启管理。先通过 iStoreOS 原生网络页面建立并启用 wg。

## 当前还有限制吗？

仍使用 wg 接口、UDP 51820；主 IPv4 支持 /8–/30，单个客户端为 /32，多个 IPv4 时取第一个作主网段并排除全部本地 IPv4。IPv6 尚不支持。无需先有 3 个客户端。

以下 0.3.1 和更早问答是历史说明；其中固定地址池/提示不自动变化的描述已由 0.4.0 替代。

# 常见问题

## AllowedIPs 怎么填写？

这里是导出到客户端配置中、针对服务端 Peer 的 AllowedIPs，不是服务端给单个客户端分配的 `/32`。

| 示例 | 客户端效果 |
| --- | --- |
| `192.168.66.0/24, 192.168.95.0/24` | 仅这些目标网段走 VPN；家庭 LAN 不同就替换第二项 |
| `0.0.0.0/0` | 所有 IPv4 目标走 VPN，需要服务端转发、防火墙/NAT 支持 |
| 两个家庭网段再加 `0.0.0.0/0` | 同样覆盖全部 IPv4，前两个网段可省略 |

当前版本仅支持 IPv4，不能填写 `::/0`；只填 IPv4 默认路由不代表 IPv6 也进入隧道。插件不会自动建立上网所需的 NAT 或更改其他代理软件策略。

## 客户端 DNS 有什么影响？

指定连接隧道后的域名解析服务器。若 `192.168.95.1` 是家里的 DNS，且 VPN 能到达它并允许 DNS 请求，可以使用其解析服务。DNS 不通时可能握手正常、访问 IP 正常，但网页域名打不开。AllowedIPs 须覆盖 DNS 地址。

留空会省略导出配置的 DNS 字段，通常沿用客户端系统设置；具体行为取决于客户端平台及其他 DNS 软件。DNS 本身不决定所有流量是否经过 VPN。应用单独设置的加密 DNS 也可能不遵循接口 DNS。

导出设置只影响之后下载或扫码的配置；已导入的客户端须同步修改或重新导入。

## 没连接为什么还有少量下载计数？

界面从服务器接口计数计算速率。客户端离线后服务器仍可能向旧端点尝试发送排队数据或重传，这不代表客户端收到数据。握手也不是实时在线检测；本版按最近握手估计活跃程度，握手过期时显示速率归零。累计不会因此清空。

## 按钮为什么不可用？

先运行 `wgmanager doctor`。`monitor` 为默认只读；符合适用条件后使用 `enable-management`。原有客户端需要另行 `manage-existing`。健康异常、漂移或待恢复事务会限制写入。未保存原私钥的旧客户端没有完整配置/二维码导出入口。

不要通过修改页面 disabled 属性或删除状态文件绕过限制。

## “后台采样未启动”影响 VPN 吗？

不影响 WireGuard 的转发。它表示关闭页面后不会持续后台采样，累计可能不完整。需要时按 README 启用插件自己的采样服务；这与 rpcd 对象注册是两件事。

## 新系统没有客户端，或者只有一两个，能开启管理吗？

0.3.1 起没有客户端数量门槛，支持 0 个、1 个、2 个及更多客户端。旧版 0.3.0 的 `BASELINE_INCOMPLETE` 是针对最初目标环境保留的限制，不是 WireGuard 协议要求；升级到 0.3.1 可移除该限制，无需创建假 Peer。

新系统仍需先配置并运行 `wg` 接口（服务端 `192.168.66.1/24`、UDP `51820`）及必要网络转发。插件负责客户端管理，不会自动搭建服务端。没有旧客户端时无需接管；有旧客户端时按实际集合保护，显式 `manage-existing` 后才能修改。

## 兼容其他网段、端口和 IPv6 吗？

目前接口 `wg`、端口 `51820`、服务器地址 `192.168.66.1/24` 和客户端池固定在代码中，IPv6 分配及导出未实现。修改导出 AllowedIPs 不会改变这些服务端约束。


## 改了 iStoreOS 中 wg 的 IP，地址池和新增提示会自动变吗？

0.3.1 不会。当前读取接口地址用于核对固定配置，自动分配逻辑和弹窗提示仍是 `192.168.66.2–254`。改成其他网段会阻止管理，不能只改提示文字来扩大实际可用范围。

导出 AllowedIPs 是另一项设置，可以在界面自定义；它决定客户端哪些目标经 VPN，不会改服务端接口地址或客户端地址池。修改导出设置不会自动更新已导入手机的配置。

完整说明见 [地址配置说明](ADDRESS-CONFIGURATION.md)。
